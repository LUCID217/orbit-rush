## Needs Eugene
Each item gives the door (one-way or two-way), the blast radius, and a proposed check or rule. They are in priority order.

**Release blockers (revenue)**
1. **Interstitials never show.** `index.html:2472-2473` listens for `onInterstitialAdLoaded` and `onInterstitialAdDismissed`, but v7 emits `interstitialAdLoaded` and `interstitialAdDismissed`. Because of that, `interstitialLoaded` stays false and `interstitialPending` is never set. The result is zero interstitial revenue and no error. ADR 0003 says the event names are "v7-specific", but these two are wrong for v7. *Fix:* rename the two strings. *Door:* two-way. *Blast radius:* big (ads; players will start seeing interstitials). *Check:* added as a WARN; make it FAIL after the fix.
2. **Each coin pack can only be bought once per player.** `index.html:2643` calls `purchaseProduct` without `isConsumable:true`, and the plugin's default is `false`. The plugin acknowledges the purchase but never consumes it, so Play then answers "item already owned". *Fix:* add `isConsumable:true` for coin packs only. *Door:* two-way. *Blast radius:* big (billing). *Check:* added as a WARN.
3. **Remove Ads can't be restored.** In 7.x, `restorePurchases()` resolves to nothing, so `index.html:2684` always gets an empty list and shows "No purchases to restore". Play expects non-consumables to be restorable. *Fix:* after `restorePurchases()`, read `NP.getPurchases({productType:"inapp"})` and look for the Remove Ads product. Also consider checking this silently at boot, so a reinstall gets its ad-free state back without the player tapping anything. *Door:* two-way. *Blast radius:* big (billing). *Check:* added as a WARN.
4. **Pending purchases are paid out before the money arrives.** Cash and convenience-store payments are common in LATAM and SEA, and they arrive as PENDING (`purchaseState "0"`). `buyCoinPack` and `buyRemoveAds` grant as soon as `purchaseProduct` resolves, without checking `purchaseState==="1"`. Nothing picks up a purchase that completes later, or one where the app died mid-flow, so paid coins can be lost. *Fix:* only grant on state `"1"`, and on boot run `getPurchases()` to grant and consume anything outstanding. *Door:* two-way. *Blast radius:* big (billing). *Rule (CODING_STANDARDS):* "Grant IAP only on purchaseState 1; reconcile getPurchases() at boot."
5. **Ads never retry after a failed load.** There are no `…FailedToLoad` listeners, and the next `prepRewarded`/`prepInterstitial` only runs after an ad is dismissed. One failed load (for example, offline at launch, which is common on prepaid data) means no rewarded "CONTINUE" or "2× XP" for the rest of the session. *Fix:* on FailedToLoad, retry with backoff. *Door:* two-way. *Blast radius:* big (ads). *Check:* WARN if any `prepare*` exists without a matching `FailedToLoad` listener.

**Economy bugs (players can farm)**

6. **Every revive pays the run's coins again.** `gameOver()` adds coins for the whole run score plus `runPerfects` bonus each time (`index.html:2236`), and a revive keeps both totals. Revive at 150 points, die at 151, and you're paid for 301 points; the first coin revive (60) more than pays for itself. `runsPlayed` and "Play N runs" missions also count every revive death as a new run (line 2251). *Fix:* pay only the score earned since the last payout this run, and count runs in `startRun`. *Door:* two-way. *Blast radius:* big (economy). *Check:* a node test that simulates death, revive, death and asserts total coins = f(final score).
7. **2× XP can be taken again after a revive, and it doubles earlier bonuses.** `doubleXPUsed` resets on every game over, and `runXPGained` includes the previous bonus (line 2566). *Fix:* make it once per run, or double only the XP earned since the last payout. *Door:* two-way. *Blast radius:* big (economy). *Check:* same test as item 6.

**Robustness**

8. **Old WebViews can't start the game.** `loadSave()` uses `structuredClone` (WebView 98+). On older WebViews it throws, and the `catch` fallback calls it again (line 689), so the script block dies and the game never boots. `minSdk` is 23, and the target markets have many old, rarely updated phones. *Fix:* use `JSON.parse(JSON.stringify(...))`. The save format doesn't change. *Door:* two-way. *Blast radius:* big (save loading). *Check:* added as a WARN. Optionally also fail on syntax newer than a chosen WebView baseline.
9. **A corrupt save is silently replaced.** The next `save()` overwrites the player's real progress, including the Remove Ads flag. *Fix:* copy the raw blob to `SAVE_KEY+".bak"` before resetting. *Door:* two-way. *Blast radius:* big (saves). *Rule:* "Never overwrite an unreadable save without keeping a copy."
10. **Edge-to-edge (targetSdk 36).** Android 15+ forces edge-to-edge. Nothing in `capacitor.config.json` adjusts margins, so check on an Android 15/16 phone that the pause button, HUD and banner clear the status bar and gesture bar. Also note that Android 16 ignores `screenOrientation="portrait"` on tablets and foldables; the game's landscape fit should cope, but test it. *Door:* two-way. *Blast radius:* small. *Check:* add it to a pre-upload device checklist in README.

**Spec drift (docs vs code)**

11. **The traffic-light assist promises more than it does.** `CONFIG` (line 395) and the render comment say green is "a guaranteed perfect", but once rings move (n ≥ `MOVE_START_N`) the light reads the ring's position now, not where it will be on arrival. Green can then end in a plain hit or a miss, which works against ADR 0006 (fair, no surprises). *Decide:* either predict the ring's position on arrival, or change the wording and accept the limit. *Door:* two-way. *Blast radius:* big (scoring feel).
12. **`capture()` doesn't call `classifyShot()`.** It repeats the threshold (line 1443: "keep them identical"). CODING_STANDARDS says hit detection and scoring use one function. *Fix:* have capture call `classifyShot`/a shared `isPerfect(perp, ring)`. *Door:* two-way. *Blast radius:* big (scoring). *Check:* FAIL if `r*ring.pf`/`.pf` appears outside `classifyShot`.
13. **Tuning numbers outside `CONFIG` (ADR 0002).** Some change gameplay or the economy:
    - `moveSpeed` growth `n*0.02` (line 1375)
    - spawn margin `70` (line 1388)
    - miss distance `ring.r+10` (line 1642)
    - daily-streak cap `10` (line 1267)
    - mission targets and XP rewards (`n*15`, `n*60`, `xp:1500`… lines 1068-1073)
    - rebirth-mission gate `0.6`
    - free-save pull-back `260`
    - crew new-best floor `prevBest>=5` (line 2259)
    - game-over "only N from best" `max(3, 25%)`

    *Door:* two-way. *Blast radius:* big (difficulty/economy) if values change; a pure move is safe. *Check:* WARN on numeric literals inside `Game.orbitSpeed…moveSpeed`, `spawnNext`, `Missions.gen`, `checkDaily`.
14. **Glossary drift:**
    - **Rank**: there's no rank by level. `RANKS` is a local list, and `milestoneTitle()` picks a random rank by hash, shown only as a toast every 10th level (so level 100 can be "Pilot").
    - **Revive**: the glossary leaves out the once-per-run rewarded-ad continue (`Game.revived`).
    - **Near miss**: "missed by N px" shows on *every* death (line 2216), not only within `NEAR_MISS_SHOW_PX`.
    - **`Game.rings`**: not declared in the `Game` object; it's first set in `startRun`.

    *Decide* whether the code or the glossary is right. *Door:* two-way. *Blast radius:* small. *Rule:* "A glossary entry names a symbol that exists" (a check can grep each `In code` cell).
15. **README drift:**
    - Language order leaves out the ETS site's saved choice (`localStorage "ets.lang"`), which sits between the player's choice and the device language.
    - README says the invite is "never again after closed twice", but starting a new run or going Home while the card is open also counts as a close (line 2760). Two quiet retries end the invite for good.

    *Door:* two-way. *Blast radius:* small.
16. **ADR 0006 says ads have "a cap and a minimum interval".** There's an every-3-deaths cadence and a 60 s interval, but no per-session cap. Either add `ADS_INTERSTITIAL_MAX_PER_SESSION` or reword the ADR. *Door:* two-way. *Blast radius:* big (ads).
